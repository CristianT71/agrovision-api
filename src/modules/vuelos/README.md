# Vuelos privados del administrador

El contrato del panel se implementó en `/api/vuelos`. El dominio define puertos de entrada y salida; los casos de uso coordinan persistencia, disco, metadata, firma y auditoría. El módulo no modifica solicitudes ni ubicación. Los listados omiten rutas internas y metadata cruda; el detalle de archivo entrega `metadatosCrudos` y, para SRT, su `traza` acotada.

Configurar `VUELOS_URL_SECRET` (obligatoria, diferente de `JWT_SECRET` y `UPLOAD_URL_SECRET`), `VUELOS_MAX_ARCHIVO_MB` (2048 por defecto) y `UPLOADS_DIR` (ya existente). No se ejecutaron migraciones. La migración `1793400000000-CrearVuelos.ts` tiene reversión y crea también la auditoría con triggers contra UPDATE, DELETE y TRUNCATE. Crear/borrar vuelo y su auditoría comparten transacción; una auditoría fallida impide entregar enlaces.

Las subidas usan un StorageEngine de multer que escribe por stream y calcula SHA-256 en un Transform. Las rutas son `UPLOADS_DIR/vuelos/<vueloId>/<archivoId>.<ext>`; el nombre original solo se conserva como dato y nombre de descarga codificado. Se validan firma, extensión, UTF-8 completo del SRT y límite mientras se escribe. La clave única y el bloqueo de vuelo resuelven subidas concurrentes duplicadas. El disco se limpia después de confirmar el borrado de filas; los fallos de limpieza se registran únicamente con código de error, sin rutas. Una limpieza fallida puede requerir retirar archivos residuales del disco; no deja registros huérfanos.

El resumen agrega en PostgreSQL; la traza selecciona solo 2001 filas ordenadas por captura, creación e id para entregar hasta 2000 puntos y anunciar `truncado`. No mezcla puntos SRT con los puntos por archivo que exige el contrato. Las miniaturas JPEG/TIFF usan sharp con lado largo hasta 320 px y normalización de contraste para TIFF, incluidos 16 bits. Un fallo de miniatura produce `urlMiniatura: null`. TIFF, DNG y SRT se descargan como adjuntos; JPEG, MP4 y MOV admiten disposición inline. La reproducción depende del códec del navegador.

No hay muestras reales DJI. Las pruebas usan coordenadas inventadas y archivos sintéticos temporales; no se agregaron binarios. El sufijo `_MS_*` y el formato SRT siguen **no verificados**. Se mantuvo `exifr` con XMP habilitado y lectura por segmentos; no se cambió a `exiftool-vendored`. La instalación de `exifr` y su lectura real de campos drone-dji no pudieron comprobarse aquí por falta de acceso DNS a npm. Las pruebas del adaptador usan objetos de tags simulados, no afirman compatibilidad comprobada con un dron. El video se clasifica y conserva por streaming; los bloques de metadata pueden ser nulos y la telemetría SRT se consulta en su propio archivo.

Validación: `npx jest --runInBand --watch=false src/modules/vuelos` y `npx tsc --noEmit`. Las pruebas HTTP usan Nest, Express y multer reales con un transporte en memoria, porque el sandbox no permite abrir sockets. Tampoco se comprobó el SQL contra un PostgreSQL real en este entorno.
